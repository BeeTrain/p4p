# Оценка интерфейса p4p

Интерфейс используется для трёх задач: настроить правила, проверить маскирование и разобраться с запросами. Раньше длинные пояснения и карточки ошибок занимали большую часть окна, действия сохранения исчезали при прокрутке, а над вводом было два визуально независимых элемента одного плагина.

## Что изменено

- Окно занимает 80% высоты окна OpenCode. Прокручивается содержимое, шапка с сохранением, перезагрузкой и состоянием остаётся на месте.
- Импорт, экспорт и маскирование объединены в одну строку. Статус показывает сохранённое состояние, а подпись отдельно сообщает о несохранённых изменениях.
- Справочные пояснения перенесены в значки `i`. Подсказки открываются мышью, касанием и клавиатурой, закрываются по `Escape`. Подписи полей, лимит словаря и сообщение об отсутствии хостов остаются видимыми.
- Переключатели диагностики расположены в две колонки при достаточной ширине и в одну в узком окне.
- Журнал использует компактные строки с постоянными колонками. Цвет каждого индикатора сопровождается текстом, поэтому состояние различимо без восприятия цвета.
- Над вводом одна визуальная панель `p4p | щит | шестерёнка`. Действия сохраняют отдельный фокус и доступные названия. У иконок одинаковые отступы.

## Следующие улучшения

1. **Фильтр статуса и поиск по модели/сессии в журнале.** После добавления успешных запросов ошибки будут быстрее теряться среди записей. Фильтрация решает это без увеличения высоты каждой строки.
2. **Раскрытие деталей строки.** По нажатию показывать полный текст ошибки, длительность и токены, оставляя основной список компактным. JSON сохранить как действие для выгрузки.
3. **Вкладки «Правила», «Проверка», «Журнал».** Если журнал используется регулярно, вкладки сократят прокрутку. Общая шапка и черновик настроек должны сохраняться при переключении; при текущем размере формы это отдельный следующий шаг, а не обязательное усложнение.
4. **Явное предупреждение о несохранённых изменениях при закрытии окна.** Сейчас состояние видно в шапке, но защита от случайного закрытия полезна при редактировании длинного словаря. Стоит одинаково обработать крестик, Escape и нажатие вне окна.

## На какие правила опирается оценка

- [W3C: Tooltip Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) — открытие по наведению и фокусу, связь через `aria-describedby`, закрытие по Escape.
- [W3C: дополнительные признаки при использовании цвета](https://www.w3.org/WAI/WCAG21/Techniques/general/G182) — статус нельзя передавать только зелёным, красным или оранжевым цветом.
- [Nielsen Norman Group: Tooltip Guidelines](https://www.nngroup.com/articles/tooltip-guidelines/) — подсказки подходят для дополнительной справки, а необходимые подписи и ограничения должны оставаться на экране.
- [Carbon Design System: Data table](https://v10.carbondesignsystem.com/components/data-table/usage/) — повторяющиеся записи удобнее сканировать в строках с общими колонками и панелью действий.

Эти решения опираются на устойчивые правила доступности и плотности интерфейса. Прозрачность, анимация и другие декоративные тенденции здесь не улучшают основные задачи пользователя.
