# p4p

Плагин OpenCode для маскирования выбранных слов и совпадений регулярных выражений в запросах моделей. Подходит для локального обезличивания секретов в разрешённых к отправке данных. Словарь и список хостов изначально пустые.

В комплекте: серверный плагин, команды `p4p`, страница **Settings → p4p**, боковая панель, кнопки над вводом сообщения и команда `/p4p` в OpenCode Desktop. Настройки общие, изменения действуют со следующего запроса без перезапуска.

## Требования и установка

- Node.js 22+, Python 3.9+ (`python3`; в Windows `python` или переменная `P4P_PYTHON`).
- OpenCode CLI / Desktop 2.2.5–2.2.6. Проверено на этих версиях. GUI API OpenCode экспериментальный, совместимость с другими версиями требует проверки.

Готовый пакет версии **1.2.0** опубликован в [GitHub Releases](https://github.com/BeeTrain/p4p/releases/tag/v1.2.0). Он содержит собранные серверную и GUI-части и скрипты проверки кеша и производительности; компиляция на машине пользователя не нужна.

```sh
curl -fL -o p4p-1.2.0.tgz https://github.com/BeeTrain/p4p/releases/download/v1.2.0/p4p-1.2.0.tgz
npm install --global ./p4p-1.2.0.tgz
p4p init
p4p install --opencode-config /путь/к/opencode.jsonc
```

Для установки из исходников:

```sh
git clone https://github.com/BeeTrain/p4p.git
cd p4p
npm ci
npm run build
node ./dist/cli.js init
```

Подключите плагин в нужный файл настроек OpenCode. Укажите реальный путь к своему `opencode.json` или `opencode.jsonc`:

```sh
node ./dist/cli.js install --opencode-config /путь/к/opencode.jsonc
```

Команда сохраняет остальные настройки и комментарии JSONC, добавляет локальную папку плагина в `plugins` и передаёт абсолютный путь к конфигурации p4p. Повторный запуск не дублирует запись. Перезапустите OpenCode после подключения. Папку p4p после этого перемещать нельзя без повторного подключения.

Можно подключить вручную:

```json
{
  "plugins": [
    {
      "package": "/абсолютный/путь/к/p4p",
      "options": { "config": "/абсолютный/путь/к/p4p-config.json" }
    }
  ]
}
```

При подключении вручную без `options.config` используются `P4P_CONFIG`, затем `$XDG_CONFIG_HOME/p4p/config.json` или `~/.config/p4p/config.json`. CLI принимает `--config FILE`. Для удалённого сервера OpenCode Python и конфигурация должны находиться на сервере; панель редактирует именно серверный файл.

Для отдельной команды в терминале можно установить локально собранный архив:

```sh
npm pack
npm install --global ./p4p-1.2.0.tgz
p4p help
```

Пакет распространяется через GitHub Releases, в npm не публикуется: имя `p4p` там принадлежит другому проекту. Используйте архив из релиза, а не `npm install -g p4p`. Глобальная установка необязательна: вместо `p4p` используйте `node ./dist/cli.js` из собранной папки проекта.

## Импорт и экспорт конфигурации

В окне настроек доступны **Импорт JSON** и **Экспорт JSON**. Переносятся включение маскирования, весь словарь, хосты и пять параметров диагностики. Файл содержит версию формата `version: 1` и сами настройки; локальный путь, ревизия, логи запросов и таблицы восстановления в него не входят.

- **Импорт JSON** открывает выбор локального файла, проверяет JSON, хосты и Python regex, затем заполняет форму. Рабочие настройки изменяются только после нажатия **Сохранить**. При наличии несохранённых правок потребуется подтвердить их замену. Неверный файл оставляет форму и рабочую конфигурацию без изменений.
- **Экспорт JSON** проверяет и сохраняет текущие поля формы, включая несохранённые изменения. В Desktop открывается системный диалог сохранения, в браузере загружается `p4p-config.json`. Отмена диалога не изменяет настройки.

Через терминал:

```sh
p4p export ./p4p-config.json
p4p import ./p4p-config.json
p4p --config ./another-config.json import ./p4p-config.json
p4p export > ./p4p-config.json
cat ./p4p-config.json | p4p import -
p4p export ./p4p-config.json --force
```

CLI экспортирует сохранённую конфигурацию, а импорт сразу полностью заменяет настройки выбранного файла `--config` / `P4P_CONFIG`. Поддерживаются `--file FILE`, `-` для стандартного ввода/вывода и формы `p4p config import` / `p4p config export`. Без имени файла экспорт пишет чистый JSON в стандартный вывод. Существующий файл экспорта заменяется только с `--force`; для сохранения поверх рабочего файла настроек используйте импорт. Файловый экспорт CLI выполняется атомарно с правами `0600` на POSIX.

Поддержан импорт прежнего словаря `words` (буквальный текст без учёта регистра), обычного JSON настроек p4p и результата `p4p config show` с обёрткой `settings`. Пути и ревизии из импортируемого файла не используются. Пустой список хостов отключает обработку всех моделей. Лимит файла — 8 МБ. Настройки панели и CLI обновляют один файл; сохранение из панели проверяет ревизию и не перезаписывает изменения другого окна.

## Кнопки над полем ввода

В открытом чате OpenCode Desktop над полем сообщения появляется единая панель с двумя действиями:

- **Щит** — переключает общий параметр `enabled` в той же конфигурации, которую редактируют панель и CLI. Изменение действует со следующего запроса. Словарь, хосты и остальные настройки сохраняются. Уже начатые ответы продолжают восстанавливаться.
- **Шестерёнка** — открывает отдельное окно «Настройки p4p» со словарём, хостами, обработкой диагностики и предпросмотром. Шестерёнка доступна и при выключенном маскировании.

Окно настроек занимает 80% высоты окна OpenCode. Шапка с кнопками **Сохранить** и **Перезагрузить** остаётся видимой при прокрутке. Импорт, экспорт и переключатель маскирования находятся в одной строке; пояснения разделов открываются через значки `i` наведением, фокусом или нажатием. `Escape` закрывает подсказку. Зелёный или серый статус в шапке показывает сохранённое состояние; изменения формы применяются после сохранения.

Состояние меняется после подтверждения сохранения сервером. Во время сохранения повторное переключение недоступно; при ошибке отображается сообщение. Изменения из окна настроек отражаются сразу, из CLI или другого окна — при обновлении состояния, не позднее следующего опроса примерно через две секунды. Нажатия не отправляют сообщение и не изменяют черновик.

Единая панель `p4p | щит | шестерёнка` использует штатные `ComposerPill` SDK. Щит с галочкой зелёный, щит с крестиком красный; названия действий доступны при наведении и для программ чтения с экрана. Панель отображается в чатах собственного локального сервера OpenCode. В подключениях к другому серверу она скрыта, чтобы случайно не переключить локальную конфигурацию вместо удалённой. На домашнем экране и до создания сессии SDK не предоставляет эту строку; настройки остаются доступны через **Settings → p4p**.

## Словарь и хосты

```sh
p4p add 'private-value' '(?i)example-secret' 'customer-\d+'
p4p add --literal --ignore-case 'literal.value'
p4p list
p4p remove 2
p4p remove 'customer-\d+'
p4p hosts add api.example.test localhost:8080 '*.models.example.test'
p4p hosts list
p4p hosts remove localhost:8080
p4p status
p4p disable
p4p enable
```

Словарь единый: **одна строка — один Python regex**. Обычные слова являются допустимыми regex. Сопоставление по умолчанию учитывает регистр; `(?i)` отключает это. Для буквальных спецсимволов используйте экранирование (`literal\.value`) или CLI `--literal`. Совпадение ищется в любом месте текста; для целых слов используйте `\bword\b`. Пустые строки редактор пропускает. Выражения, совпадающие с пустой строкой, не допускаются.

В панели можно отредактировать весь словарь в одном поле, добавить или удалить строки, включить обработку, настроить хосты и диагностику, проверить текст до сохранения. Есть предпросмотр замаскированного и восстановленного текста и счётчики замен, логов и стектрейсов. Несохранённые изменения не влияют на запросы. При одновременном редактировании в двух окнах старое окно не перезапишет новые настройки: потребуется перезагрузить их.

Хост выбирается по адресу фактического HTTP-запроса:

- `api.example.test` — точное имя на любом порту;
- `api.example.test:443` — точное имя и порт;
- `*.example.test` — поддомены, включая вложенные, без самого `example.test`;
- `localhost:8080`, `127.0.0.1:8080`, `[::1]:8080` — локальные адреса;
- полный URL нормализуется в хост и явно заданный порт; путь не участвует в сопоставлении.

Пустой список хостов означает отсутствие обработки. Отключённое маскирование также оставляет запросы без изменений. Если OpenCode подключён через прокси, укажите хост прокси. На других хостах p4p не изменяет запросы и ответы.

## Логи и стектрейсы

```sh
p4p diagnostics show
p4p diagnostics set logs on
p4p diagnostics set stacktraces on
p4p diagnostics set marked on
p4p diagnostics set heuristics on
p4p diagnostics set tool_output off
```

Правила применяются **внутри** найденных фрагментов. Остальной текст и структура ошибки сохраняются. Поиск фрагментов:

- `marked`: ограждения Markdown `log`, `logs`, `logcat`, `console`, `stderr`, `stdout`, `stacktrace`, `traceback`, `stack`, `trace` и XML-подобные теги;
- `heuristics`: уровни TRACE/DEBUG/INFO/WARN/ERROR/FATAL, строки Android Logcat, заголовки исключений и кадры Java/Kotlin/JavaScript, Python traceback;
- `tool_output`: весь текст результата инструмента считается логом.

`logs` и `stacktraces` включены по умолчанию. При их отключении **найденные фрагменты** соответствующего типа не маскируются. Выключение `marked` или `heuristics` отключает способ распознавания, а не правила словаря. Не распознанный как диагностика текст обрабатывается обычным словарём. Эти переключатели не скрывают консольные логи самого OpenCode и его локальную историю.

## Предпросмотр

```sh
p4p preview --text 'example-secret customer-42'
p4p preview --file ./example.txt --host https://api.example.test/v1
printf '%s' 'example-secret' | p4p preview
p4p config show
p4p config path
p4p list --json
```

Предпросмотр работает локально, модель не вызывается. Он проверяет текущий словарь независимо от хоста; поле `hostMatches` отдельно показывает, применились бы правила к указанному URL. Исходный и восстановленный текст совпадают. Через панель предпросмотр использует ещё не сохранённые поля.

## Как работает восстановление

Перед модельным запросом каждое найденное значение заменяется обозначением вида `__P4P_<случайный идентификатор>_0__`. Это ссылка на локальную таблицу, без исходного значения внутри. В HTTP и WebSocket одинаковые значения сохраняют обозначения между вызовами одной сессии, агента, модели и вида вызова. Поэтому p4p сохраняет совпадение префикса одинаковых системных инструкций и истории для кеша провайдера. Параллельное маскирование одного контекста выполняется по очереди, чтобы новым значениям не назначались одинаковые обозначения.

Таблицы хранятся только в памяти процесса. В HTTP они дополнительно разделены по адресу запроса и заголовкам авторизации: в ключе хранится хеш, сами заголовки туда не записываются. Обновление правил и временное выключение маскирования сохраняют прежние обозначения. Контексты удаляются при удалении сессии, выгрузке плагина или после часа простоя. Лимиты HTTP: 128 контекстов, 10 000 значений и 8 МБ на таблицу, 32 МБ суммарно; превышение останавливает отправку запроса. Вызовы HTTP API ядра без идентификатора сессии используют отдельную таблицу на запрос.

Для каждого HTTP-ответа сохраняется собственный снимок таблицы на момент запроса; новые замены из параллельных вызовов в него не попадают. Поддержаны обычный JSON и SSE: обозначения восстанавливаются даже при разделении между сетевыми пакетами и JSON-дельтами, включая аргументы вызовов инструментов. OpenCode получает восстановленный текст **до** выполнения инструмента. Локальная история и файлы содержат исходные значения; в следующем запросе история маскируется заново с прежними обозначениями.

Восстановление возможно, только если модель вернула обозначение без изменений. Если она перефразировала или повредила его, угадать оригинал невозможно. Маскирование также уменьшает доступный модели смысловой контекст. Не используйте правила, меняющие смысл структурных разделителей JSON или весь протокол.

Маскируются текстовые поля сообщений, системных инструкций, описания инструментов и текстовые элементы схем. Служебные ID, роли, имена моделей и типов, URL изображений и бинарные поля сохраняются. Заголовки авторизации и адрес запроса не изменяются: они необходимы для подключения. p4p не анализирует изображения, вложения, произвольный сетевой трафик и вызовы других программ.

Для выбранных хостов поддержаны HTTP/JSON и SSE, включая ответы gzip, а также WebSocket Responses API. Другие WebSocket-протоколы, включая Realtime/audio, пока не поддерживаются: исходящее сообщение неизвестного протокола при активном маскировании отклоняется. Неподдерживаемый формат, неверный regex или превышение времени обработки вызывают ошибку; автоматической отправки исходного текста нет.

При включённой записи p4p сохраняет локально журнал запросов для включённых выбранных хостов: успешные, неуспешные и без подтверждённого результата. Таблицы восстановления на диск не записываются. Формат и очистка журнала описаны ниже. Это не шифрование и не средство обхода политик доступа. Пользователь отвечает за разрешённость отправки данных выбранной модели. Словари прежних проектов и данные их запросов в этот репозиторий не перенесены.

## Настройки и ограничения

Файл JSON сохраняется атомарно с правами `0600` на POSIX. Изменения CLI сериализуются файловой блокировкой, панель использует контроль версии содержимого. Конфигурация перечитывается перед каждым запросом.

```json
{
  "version": 1,
  "enabled": true,
  "hosts": ["api.example.test"],
  "patterns": ["(?i)example-secret", "customer-\\d+"],
  "diagnostics": {
    "logs": true,
    "stacktraces": true,
    "marked": true,
    "heuristics": true,
    "tool_output": false
  }
}
```

Лимиты: 600 паттернов до 2000 символов, 200 хостов, 256 000 символов предпросмотра, 16 МБ HTTP-запроса и буфера потокового восстановления, 32 МБ JSON-ответа. Regex обрабатываются в постоянном пуле Python с лимитом 5 секунд на операцию, без завершения самого OpenCode. Зависший процесс заменяется; исходный запрос при ошибке не отправляется. Сложные regex стоит проверять в предпросмотре.

Неизменившиеся строки истории используют ограниченный кеш найденных совпадений с учётом правил, диагностики и контекста сессии. Таблица замен применяется заново, статистика сохраняется. Ответы JSON и SSE восстанавливаются в Node.js без запуска Python. Подробнее об устройстве, ограничениях и локальном бенчмарке — в [описании производительности](docs/performance.md).

Для повторяемого сравнения кеша с p4p и без него есть [парный A/B-тест](scripts/cache-benchmark/README.md): `npm run test:cache -- --model provider/model --dry-run` проверяет сценарий локально, запуск без `--dry-run` выполняет реальные вызовы. По умолчанию — 10 пар сессий по 20 запросов в каждом режиме, независимые префиксы, чередование режимов и доверительный интервал по парам сессий. Рабочие настройки не изменяются; метрики сохраняются в `test-results/cache-benchmark/`.

Чтобы использовать p4p с uitest-loop, добавьте пакет в конфигурацию OpenCode, **которую loop фактически создаёт для исполнителя**. Изолированный запуск может не читать пользовательский список плагинов. Двойное маскирование на стороне loop и плагина не рекомендуется. Интеграция loop и его текущие настройки автоматически не меняются.

## Журнал запросов и выгрузка JSON

Откройте шестерёнку над вводом или **Settings → p4p → Журнал запросов**, выберите запись и нажмите **JSON ↓**. В Desktop открывается системное сохранение файла. Кнопка **Обновить запросы** перечитывает журнал; пока панель открыта, список также обновляется каждые три секунды. **Очистить журнал** удаляет сохранённые записи после подтверждения и не меняет конфигурацию.

```sh
p4p requests list
p4p requests list --json
p4p requests export latest ./failed-request.json
p4p requests export REQUEST_ID ./failed-request.json
p4p requests export latest > ./failed-request.json
p4p requests clear
```

Можно использовать общий `--config FILE` для выбора конфигурации. Существующий файл экспорта защищён от перезаписи; для замены нужен `--force`. Рабочий конфиг перезаписывать отчётом нельзя.

Файл называется `model-request-<id>.json`, как в дашборде uitest-loop: одна запись со статусом `succeeded`, `failed` или `unknown`, `source`, `request`, `error`, `http_status`, `response_preview`, адресом, моделью, сессией, временем, размерами и доступными метриками. Поле `request` содержит запрос до применения словаря; дополнительное поле `masked_request` — тело, отправляемое после обработки плагином. Известные секреты скрыты в обоих полях. При включённых параллельно других плагинах тело может дополнительно измениться их перехватчиками.

Поддержаны HTTP-ошибки 4xx/5xx, ошибки JSON/SSE, ошибки потока и события ошибок OpenCode, а также ошибки Responses API WebSocket. В WebSocket сохраняется физическое сообщение `response.create`; при инкрементальном продолжении прошлый контекст остаётся на стороне модели. При ошибке подключения до отправки кадра доступна только информация о подключении. Если событие OpenCode нельзя однозначно связать с параллельным запросом, сохраняется запись с `source: "transcript"` без подстановки чужого тела. Ограничения фиксируются в `coverage`; поля loop вроде `job`, `prompt`, `command` или недоступные метрики остаются `null`/пустыми. Полностью восстановить данные, которых нет в hooks OpenCode, нельзя.

Переключатель **Записывать запросы** управляет настройкой `recordRequests` и применяется к новым запросам после нажатия **Сохранить**. По умолчанию запись включена; прежние конфигурации совместимы. При выключении записи сохранённые данные остаются доступны. Сохраняются **новые запросы при включённом p4p для выбранных хостов**, в том числе с пустым словарём. Старые запросы не восстанавливаются.

Журнал отображается компактными строками. Зелёный индикатор и «Успешно» означают подтверждённое завершение JSON/SSE/WebSocket; красный и «Ошибка» — явный сбой HTTP, модели или потока; оранжевый и «Без результата» — ожидание ответа, отмену до завершения или неподтверждённый конец потока. HTTP 200 без события завершения SSE сам по себе не делает запрос успешным. Начальная запись сохраняется до отправки: при обрыве процесса запрос остаётся в журнале с `unknown`. Для совместимости с прежними версиями журнал хранится рядом с конфигом в `failed-requests/<идентификатор-конфига>/`: до 50 записей, 128 МБ суммарно и семи дней. Ограничения применяются при записи; срок хранения также проверяется при просмотре списка. Записи имеют права `0600` на POSIX. Ошибка записи журнала не останавливает запрос модели и показывается в панели.

Заголовки запросов не сохраняются; из адреса удаляются параметры, логин и пароль. Значения известных ключей доступа, паролей и авторизации скрываются в телах и ошибках. Отчёт всё равно содержит исходный текст запроса, поэтому перед передачей файла другому человеку проверьте его содержимое. Таблицы замен в JSON не выгружаются. Тело ограничено 16 МБ, превью ответа — 16 000 символов, одна запись — 36 МБ; при превышении лимитов память освобождается, а причина указывается в `coverage`.

## Разработка и проверки

```sh
npm ci
npm run typecheck
npm test
npm run test:ui
OPENCODE_BIN=/путь/к/opencode npm run test:live
P4P_LIVE_FAILURE=1 OPENCODE_BIN=/путь/к/opencode npm run test:live
```

`npm test` проверяет движок, потоковое восстановление, конфигурацию, хосты, журнал запросов и CLI. Интерфейс проверяет скачивание JSON в панели и через системное сохранение Desktop; live-проверка также подтверждает захват HTTP 422 и ошибки WebSocket настоящими перехватчиками OpenCode. Live-проверка запускает настоящий OpenCode с временным проектом и локальной тестовой моделью: маскирование запроса, восстановление аргументов команды, выполнение, повторное маскирование истории и итоговый ответ. Режим `P4P_LIVE_FAILURE=1` проверяет, что ошибка regex останавливает отправку запроса. Внешняя модель и реальные данные не используются.

Проверка интерфейса использует установленный Google Chrome, запускает редактор с настоящим локальным движком и проверяет сохранение, предпросмотр, ошибки и узкую панель. Она не меняет настройки вашего OpenCode. Сам GUI-пакет собирается официальным preset SDK; отображение в окне Desktop дополнительно зависит от его версии и включения плагина.

## WebSocket

Отдельный переключатель p4p не нужен: словарь, хосты и настройки диагностики общие для обоих транспортов. При HTTP-адресе провайдера OpenCode сам открывает соответствующий `ws://` или `wss://` адрес. В p4p укажите его фактический хост и порт.

Для провайдера с протоколом Responses API включите транспорт в конфигурации OpenCode:

```json
{
  "providers": {
    "openai": {
      "settings": { "transport": "websocket" }
    }
  }
}
```

Для собственного совместимого провайдера используйте пакет `@opencode/ai/providers/openai`, его `settings.baseURL`, разрешённые учётные данные и `settings.transport: "websocket"`. Провайдер должен поддерживать Responses API WebSocket. Плагин не выбирает транспорт за OpenCode и не преобразует Chat Completions в Responses API.

p4p обрабатывает исходящие `response.create` и управляющий `response.cancel`. В ответах восстанавливаются дельты текста, reasoning, отказов и аргументов инструментов, а также итоговые снимки текста и результатов. Разделённые обозначения собираются независимо по ответам, элементам, частям и `stream_id`. Итоговые события сохраняют типы и содержат полный восстановленный текст, включая обычные окончания `_` и `__`. ID событий, ответов, вызовов и потоков, а также зашифрованные поля не изменяются.

Таблицы разделены по сессии, агенту, модели и виду вызова. Смена адреса или заголовков подключения сбрасывает соответствующий контекст; сами заголовки не записываются в состояние — сравнивается их хеш. Если соединение разрывается при прежних параметрах, таблица остаётся доступной для повторного полного запроса. HTTP fallback OpenCode продолжает обрабатываться HTTP-перехватчиками p4p.

Изменения словаря применяются к следующему вызову. При выключении маскирования новые значения больше не заменяются; ранее созданные обозначения в сохранённом сервером контексте продолжают восстанавливаться до очистки контекста. При отмене очищаются незавершённые фрагменты, при удалении сессии или выгрузке плагина — вся её таблица. Неактивные контексты удаляются после часа простоя; активные ответы не удаляются по таймеру. Таблицы не сохраняются на диск. После перезапуска плагина или истечения срока хранения продолжение с неизвестным `previous_response_id` отклоняется: потребуется новая сессия или полный запрос.

Ограничения: 128 контекстов, до 10 000 замен и ID ответов на контекст, до 8 МБ таблицы одного контекста и 32 МБ суммарно, до 1024 незавершённых фрагментов. Входящее или исходящее сообщение — до 16 МБ, восстановленное — до 32 МБ. При превышении лимита вызов останавливается. OpenCode 2.2.5 может показывать общую ошибку потока вместо причины исключения из WebSocket-перехватчика; неверные правила можно проверить в панели или `p4p preview`.

Проверки WebSocket с настоящим OpenCode и локальной тестовой моделью:

```sh
OPENCODE_BIN=/путь/к/opencode npm run test:live
P4P_LIVE_TEST=1 P4P_WS_RECONNECT=1 OPENCODE_BIN=/путь/к/opencode node --test test/websocket-live.test.mjs
P4P_LIVE_TEST=1 P4P_WS_FAILURE=1 OPENCODE_BIN=/путь/к/opencode node --test test/websocket-live.test.mjs
```

Обычная проверка подтверждает одно соединение, продолжение с `previous_response_id`, восстановление команды перед выполнением и маскирование её вывода. Режим переподключения принудительно закрывает первый сокет; режим ошибки проверяет, что неверный regex не открывает сокет и не отправляет сообщение.

Первичные источники: [серверные hooks](https://opencode.ai/v2/docs/build/plugins/server), [GUI SDK](https://opencode.ai/v2/docs/build/plugins/gui), [RPC](https://opencode.ai/v2/docs/build/plugins/rpc).
