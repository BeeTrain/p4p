# batya

Плагин OpenCode для маскирования выбранных слов и совпадений регулярных выражений в запросах моделей. Подходит для локального обезличивания секретов в разрешённых к отправке данных. Словарь и список хостов изначально пустые.

В комплекте: серверный плагин, команды `batya`, страница **Settings → Batya**, боковая панель и команда `/batya` в OpenCode Desktop. Настройки общие, изменения действуют со следующего запроса без перезапуска.

## Требования и установка

- Node.js 22+, Python 3.9+ (`python3`; в Windows `python` или переменная `BATYA_PYTHON`).
- OpenCode CLI / Desktop 2.2.5. Проверено на этой версии. GUI API OpenCode экспериментальный, совместимость с другими версиями требует проверки.

```sh
git clone https://github.com/BeeTrain/batya.git
cd batya
npm ci
npm run build
node ./dist/cli.js init
```

Подключите плагин в нужный файл настроек OpenCode. Укажите реальный путь к своему `opencode.json` или `opencode.jsonc`:

```sh
node ./dist/cli.js install --opencode-config /путь/к/opencode.jsonc
```

Команда сохраняет остальные настройки и комментарии JSONC, добавляет локальную папку плагина в `plugins` и передаёт абсолютный путь к конфигурации Batya. Повторный запуск не дублирует запись. Перезапустите OpenCode после подключения. Папку batya после этого перемещать нельзя без повторного подключения.

Можно подключить вручную:

```json
{
  "plugins": [
    {
      "package": "/абсолютный/путь/к/batya",
      "options": { "config": "/абсолютный/путь/к/batya-config.json" }
    }
  ]
}
```

При подключении вручную без `options.config` используются `BATYA_CONFIG`, затем `$XDG_CONFIG_HOME/batya/config.json` или `~/.config/batya/config.json`. CLI принимает `--config FILE`. Для удалённого сервера OpenCode Python и конфигурация должны находиться на сервере; панель редактирует именно серверный файл.

Для отдельной команды в терминале можно установить локально собранный архив:

```sh
npm pack
npm install --global ./batya-0.1.0.tgz
batya help
```

Пакет не опубликован в npm. Глобальная установка необязательна: вместо `batya` используйте `node ./dist/cli.js`.

## Словарь и хосты

```sh
batya add 'private-value' '(?i)example-secret' 'customer-\d+'
batya add --literal --ignore-case 'literal.value'
batya list
batya remove 2
batya remove 'customer-\d+'
batya hosts add api.example.test localhost:8080 '*.models.example.test'
batya hosts list
batya hosts remove localhost:8080
batya status
batya disable
batya enable
```

Словарь единый: **одна строка — один Python regex**. Обычные слова являются допустимыми regex. Сопоставление по умолчанию учитывает регистр; `(?i)` отключает это. Для буквальных спецсимволов используйте экранирование (`literal\.value`) или CLI `--literal`. Совпадение ищется в любом месте текста; для целых слов используйте `\bword\b`. Пустые строки редактор пропускает. Выражения, совпадающие с пустой строкой, не допускаются.

В панели можно отредактировать весь словарь в одном поле, добавить или удалить строки, включить обработку, настроить хосты и диагностику, проверить текст до сохранения. Есть предпросмотр замаскированного и восстановленного текста и счётчики замен, логов и стектрейсов. Несохранённые изменения не влияют на запросы. При одновременном редактировании в двух окнах старое окно не перезапишет новые настройки: потребуется перезагрузить их.

Хост выбирается по адресу фактического HTTP-запроса:

- `api.example.test` — точное имя на любом порту;
- `api.example.test:443` — точное имя и порт;
- `*.example.test` — поддомены, включая вложенные, без самого `example.test`;
- `localhost:8080`, `127.0.0.1:8080`, `[::1]:8080` — локальные адреса;
- полный URL нормализуется в хост и явно заданный порт; путь не участвует в сопоставлении.

Пустой список хостов означает отсутствие обработки. Отключённое маскирование также оставляет запросы без изменений. Если OpenCode подключён через прокси, укажите хост прокси. На других хостах Batya не изменяет запросы и ответы.

## Логи и стектрейсы

```sh
batya diagnostics show
batya diagnostics set logs on
batya diagnostics set stacktraces on
batya diagnostics set marked on
batya diagnostics set heuristics on
batya diagnostics set tool_output off
```

Правила применяются **внутри** найденных фрагментов. Остальной текст и структура ошибки сохраняются. Поиск фрагментов:

- `marked`: ограждения Markdown `log`, `logs`, `logcat`, `console`, `stderr`, `stdout`, `stacktrace`, `traceback`, `stack`, `trace` и XML-подобные теги;
- `heuristics`: уровни TRACE/DEBUG/INFO/WARN/ERROR/FATAL, строки Android Logcat, заголовки исключений и кадры Java/Kotlin/JavaScript, Python traceback;
- `tool_output`: весь текст результата инструмента считается логом.

`logs` и `stacktraces` включены по умолчанию. При их отключении **найденные фрагменты** соответствующего типа не маскируются. Выключение `marked` или `heuristics` отключает способ распознавания, а не правила словаря. Не распознанный как диагностика текст обрабатывается обычным словарём. Эти переключатели не скрывают консольные логи самого OpenCode и его локальную историю.

## Предпросмотр

```sh
batya preview --text 'example-secret customer-42'
batya preview --file ./example.txt --host https://api.example.test/v1
printf '%s' 'example-secret' | batya preview
batya config show
batya config path
batya list --json
```

Предпросмотр работает локально, модель не вызывается. Он проверяет текущий словарь независимо от хоста; поле `hostMatches` отдельно показывает, применились бы правила к указанному URL. Исходный и восстановленный текст совпадают. Через панель предпросмотр использует ещё не сохранённые поля.

## Как работает восстановление

Перед модельным HTTP-запросом каждое найденное значение заменяется случайным обозначением вида `__BATYA_<случайный идентификатор>_0__`. Это ссылка на локальную таблицу, без исходного значения внутри. Одинаковые значения внутри одного запроса имеют одинаковые обозначения. Для следующего запроса создаётся новая таблица.

Таблица хранится только в памяти процесса на время запроса. При получении ответа заменяются только известные этому запросу обозначения. Поддержаны обычный JSON и SSE: обозначения восстанавливаются даже при разделении между сетевыми пакетами и JSON-дельтами, включая аргументы вызовов инструментов. OpenCode получает восстановленный текст **до** выполнения инструмента. Локальная история и файлы содержат исходные значения; в следующем запросе история маскируется заново.

Восстановление возможно, только если модель вернула обозначение без изменений. Если она перефразировала или повредила его, угадать оригинал невозможно. Маскирование также уменьшает доступный модели смысловой контекст. Не используйте правила, меняющие смысл структурных разделителей JSON или весь протокол.

Маскируются текстовые поля сообщений, системных инструкций, описания инструментов и текстовые элементы схем. Служебные ID, роли, имена моделей и типов, URL изображений и бинарные поля сохраняются. Заголовки авторизации и адрес запроса не изменяются: они необходимы для подключения. Batya не анализирует изображения, вложения, произвольный сетевой трафик и вызовы других программ.

Для выбранных хостов поддержан HTTP/JSON и SSE, включая ответы gzip. WebSocket пока не поддержан: активное маскирование останавливает такой вызов с просьбой выбрать HTTP/SSE. Неподдерживаемый формат, неверный regex или превышение времени обработки вызывают ошибку; автоматической отправки исходного текста нет.

Batya не пишет тела запросов, ответы или таблицы восстановления в собственные логи. Это не шифрование и не средство обхода политик доступа. Пользователь отвечает за разрешённость отправки данных выбранной модели. Словари прежних проектов и данные их запросов в этот репозиторий не перенесены.

## Настройки и ограничения

Файл JSON сохраняется атомарно с правами `0600` на POSIX. Изменения CLI сериализуются файловой блокировкой, панель использует контроль версии содержимого. Конфигурация перечитывается перед каждым запросом.

```json
{
  "version": 1,
  "enabled": true,
  "hosts": ["api.example.test"],
  "patterns": ["(?i)example-secret", "customer-\\d+"],
  "diagnostics": {
    "logs": true,
    "stacktraces": true,
    "marked": true,
    "heuristics": true,
    "tool_output": false
  }
}
```

Лимиты: 600 паттернов до 2000 символов, 200 хостов, 256 000 символов предпросмотра, 16 МБ HTTP-запроса и буфера потокового восстановления, 32 МБ JSON-ответа. Regex обрабатываются в отдельном процессе с лимитом 5 секунд на операцию, без завершения самого OpenCode. Сложные regex стоит проверять в предпросмотре.

Чтобы использовать Batya с uitest-loop, добавьте пакет в конфигурацию OpenCode, **которую loop фактически создаёт для исполнителя**. Изолированный запуск может не читать пользовательский список плагинов. Двойное маскирование на стороне loop и плагина не рекомендуется. Интеграция loop и его текущие настройки автоматически не меняются.

## Разработка и проверки

```sh
npm ci
npm run typecheck
npm test
npm run test:ui
OPENCODE_BIN=/путь/к/opencode npm run test:live
BATYA_LIVE_FAILURE=1 OPENCODE_BIN=/путь/к/opencode npm run test:live
```

`npm test` проверяет движок, потоковое восстановление, конфигурацию, хосты и CLI. Live-проверка запускает настоящий OpenCode с временным проектом и локальной тестовой моделью: маскирование запроса, восстановление аргументов команды, выполнение, повторное маскирование истории и итоговый ответ. Режим `BATYA_LIVE_FAILURE=1` проверяет, что ошибка regex останавливает отправку запроса. Внешняя модель и реальные данные не используются.

Проверка интерфейса использует установленный Google Chrome, запускает редактор с настоящим локальным движком и проверяет сохранение, предпросмотр, ошибки и узкую панель. Она не меняет настройки вашего OpenCode. Сам GUI-пакет собирается официальным preset SDK; отображение в окне Desktop дополнительно зависит от его версии и включения плагина.

Первичные источники: [серверные hooks](https://opencode.ai/v2/docs/build/plugins/server), [GUI SDK](https://opencode.ai/v2/docs/build/plugins/gui), [RPC](https://opencode.ai/v2/docs/build/plugins/rpc).
